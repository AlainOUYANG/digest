# 入选文章原文回填设计规格

日期：2026-08-02
状态：已确认

## 目标

当 RSS 只包含标题、短简介或截断内容时，摘要阶段应在入选后读取原文正文，并基于真实内容生成摘要。修复后不得再用「未提供具体内容」「建议查阅原文」一类话术掩盖输入缺失。

## 问题根因

当前 `normalizeItem()` 只读取 `content:encoded`、`content` 和 `contentSnippet`。`selectAndSummarize()` 完成评分后，直接把归一化内容传给摘要模型，条目的 `link` 只用于最终页面展示，从未在生成阶段请求。

因此，对于只在 RSS 中发布标题或短摘要、但原文页面内容完整的条目，模型实际看不到正文。截图中的 Simon Willison 条目属于这一情况。

## 范围

本次修改包含：

- 扩充 RSS 内容字段归一化。
- 只对已入选且正文不足的非即刻条目请求原文页面。
- 从 HTML 中提取主要正文并限长后交给摘要模型。
- 原文不可用时阻止占位式或推测式摘要。
- 添加覆盖正常回填、无需回填、抓取失败和正文提取的单元测试。

本次不包含：

- 修改栏目、信息源、入选数量或评分规则。
- 引入第三方在线阅读器或正文抽取服务。
- 回写或重新生成历史期刊。
- 修改 GitHub Actions、Secrets 或部署方式。

## 数据流

```text
RSS 抓取
  -> 多字段归一化
  -> 24 小时时间窗过滤
  -> LLM 评分并选出 topN
  -> 对正文少于 300 字的非即刻入选项请求原文
  -> article/main/body 正文提取与清洗
  -> LLM 基于最多 6000 字正文生成摘要
  -> 摘要防护
  -> Markdown 渲染
```

原文请求放在评分之后，避免为 100 余个候选源逐页抓取；每期只为最终入选且内容不足的少数文章增加请求。

## 详细设计

### 1．RSS 内容归一化

`scripts/lib/feeds.mjs` 在现有字段之外读取 `summary` 和 `description`。所有候选字段先经过 `stripHtml()` 清洗，再选择清洗后最长的非空文本作为 `content`；`snippet` 取该文本的前 500 字。

RSS 阶段仍对 `content` 限长 2500 字，避免候选集合占用过多内存和评分上下文。作者、链接、来源和发布时间规则保持不变。

### 2．是否回填原文

完成评分并得到 `chosen` 后再判断：

- `section.key === 'jike'`：不抓取原文，继续按短动态摘要规则处理。
- `content.trim().length >= 300`：RSS 信息足够，不发起页面请求。
- `content.trim().length < 300`：尝试请求 `link` 原文。
- 非 `http:` 或 `https:` 链接：视为不可抓取，保留 RSS 内容。

该判断不会改变评分结果或条目顺序。

### 3．页面请求与正文提取

使用 Node.js 22 内置 `fetch`，不增加依赖。每个请求：

- 超时 10 秒。
- 只接受成功的 HTTP 响应。
- 只处理 HTML 响应；明显的非 HTML 内容直接放弃。
- 发送明确的 `User-Agent` 和 HTML `Accept` 请求头。

正文提取按 `<article>`、`<main>`、`<body>` 的优先级选取第一个有效区域。清洗时移除 `script`、`style`、`nav`、`header`、`footer`、`aside`、`noscript`、`svg` 和 `form`，再复用 `stripHtml()` 解码实体、折叠空白。

只有提取结果比现有 RSS `content` 更长时才替换；传给摘要模型前最多保留 6000 字。该长度足以覆盖文章关键事实，同时控制模型输入规模。

### 4．错误处理

单个原文请求超时、网络失败、非成功状态、非 HTML 响应或正文提取失败时：

- 记录包含来源和链接的简短错误日志，不记录页面正文。
- 保留原 RSS 内容并继续处理其他条目。
- 不将该错误计入 RSS 源失败列表，因为 RSS 抓取本身已成功。

原文回填不得使整个栏目或整期生成失败。

### 5．摘要真实性防护

摘要提示词增加两条硬约束：

- 只能总结输入文本明确提供的信息，不得从标题、作者身份或常识补写事实。
- 输入证据不足时返回空摘要，不得输出「未提供具体内容」「建议查阅原文」「值得关注后续」等占位话术。

程序对模型输出做最小校验。命中上述占位式表述的摘要会被置空，最终页面只保留标题、署名和原文链接，不发布伪摘要。即刻短动态仍可基于短文本提炼核心观点，不受 300 字门槛限制。

## 接口与可测试性

实现时将页面读取设计为可注入函数，生产环境默认使用内置 `fetch`，测试传入本地假响应，不访问公网。

建议接口：

```js
export function extractArticleText(html) {}

export async function enrichSelectedContent(items, {
  fetchImpl = globalThis.fetch,
  minContentLength = 300,
  maxContentLength = 6000,
} = {}) {}

export async function selectAndSummarize(chat, section, items, {
  enrich = enrichSelectedContent,
} = {}) {}
```

具体函数名可在实施计划中微调，但必须保留依赖注入边界，确保单元测试稳定且不访问真实网站。

## 测试方案

先写以下失败测试，再实现代码：

1. `normalizeItem()` 能读取 `summary`、`description`，并选择清洗后最长文本。
2. RSS 正文达到 300 字时不调用 `fetchImpl`。
3. 即刻条目正文不足 300 字时也不调用 `fetchImpl`。
4. 短 RSS 内容对应 Simon Willison 风格 HTML 时，能提取 `<article>` 中的具体事实，且摘要模型输入包含这些事实。
5. 页面中的导航、脚本、页脚不进入正文。
6. 超时、HTTP 错误、非 HTML 和无有效正文时保留 RSS 内容，不中断其他条目。
7. 原文正文超过 6000 字时按上限截断。
8. 模型返回占位式摘要时最终摘要为空；返回由正文支撑的摘要时正常保留。
9. 现有评分排序、两次 LLM 失败后的栏目降级和空输入行为不回归。

## 风险与取舍

- 简单的 HTML 区域优先级不等同于完整 Readability 算法，但足以覆盖语义化博客页面，且无需引入大型 DOM 依赖。提取失败会安全回退，不会阻塞整期。
- 原文站点可能限制自动访问。按需抓取、短超时和有限并发能降低影响；失败时宁可没有摘要，也不生成看似完整但没有证据的文字。
- 页面正文可能包含版权内容。正文只在生成时限长传给模型，公开页面仍只展示原创摘要和原文链接。
